# Sports Field Booking Platform

A web platform that helps users find nearby sports fields, view their details, and book them in one place, with a Women's Feature that highlights fields offering suitable options for women.

**Team:** Rahaf Alabdalh, Sarah Alkhubaizy, Dhay Aldhwayan, Zahraa Ali Alhussain

---

## Project Charter

### 1. Project Objectives

**Purpose:** To create a web platform that makes it easy for people to find nearby sports fields, view their details, and book them in one place, instead of searching across scattered sources and calling venues one by one. The platform also helps women identify sports fields that offer suitable options for them.

**Objectives:**

1. **Location-based search:** Allow users to search for nearby sports fields and view each field's details, including sport type and available facilities, by [deadline].
2. **Simple booking:** Provide a booking process that lets a user reserve an available time slot in [4] steps or fewer by [deadline].
3. **Women's Feature:** Include a feature that lets users identify fields offering suitable options for women, with verified information for at least [5] fields by [deadline].

### 3. Scope

**In-Scope**

- A web platform that lets users search for sports fields based on their location.
- Display of nearby sports fields with their basic information.
- Field details page showing the sport type and available facilities.
- A booking process for available time slots.
- A Women's Feature that helps users identify fields offering suitable options for women.

**Out-of-Scope**

- Online payment.
- Ratings and reviews.
- Advanced filters (by sport, price, distance, and availability) and full map features.
- Support for additional sports types and facilities beyond the initial set.
- Expansion to a large number of fields and locations.
- Expanding the Women's Feature beyond the basic identification of suitable fields.

### 4. Risks

| # | Risk | Category | Mitigation |
|---|---|---|---|
| 1 | Difficulty collecting accurate and up-to-date information about sports fields | Data | Start with a small, manageable number of fields and verify their information directly with owners or by visiting them. Review the data regularly. |
| 2 | Field availability schedules become inaccurate or outdated | Data | Keep the booking logic simple in the MVP, use clear time slots, and ask field owners to confirm availability. Add an update process for schedules. |
| 3 | Difficulty implementing location-based functionality effectively | Technology | Research and test the location tools early, and build a simple version first, then improve it. |
| 4 | The booking process is unclear or too complicated for users | Design | Follow the Figma design, keep the booking steps few and simple, and test with a few people from the target audience before finalizing. |
| 5 | Not delivering the MVP within the project timeline | Timeline | Focus only on in-scope features, break work into small tasks in GitHub Projects, track progress weekly, and postpone out-of-scope items. |
| 6 | Team members lack experience with required tools or technologies | Team | Schedule short learning sessions early, assign learning time, and pair team members so they can help each other. |
| 7 | Unequal workload or poor communication between team members | Team | Assign clear roles, hold regular meetings on Discord, track tasks in GitHub Projects and Notion, and raise issues early. |
| 8 | Difficulty verifying which fields offer suitable options for women | Data | Define clear criteria for what counts as "suitable" and confirm each field's information directly with the owner before publishing it. |
